# NFS Footprinting in Penetration Testing

## 📌 Overview

**NFS (Network File System)** is a distributed file system protocol that allows users to access files over a network as if they were on their local machines. It is commonly used in Unix/Linux environments. During a penetration test, NFS can be a goldmine due to misconfigurations such as world-readable or writable exports.

---

## 📦 NFS Service Information

| Parameter         | Value                                                |
|------------------|------------------------------------------------------|
| Protocol         | NFS (Network File System)                            |
| Common Versions  | NFSv2, NFSv3, NFSv4                                   |
| Default Port(s)  | TCP/UDP 2049 (NFS), 111 (Portmapper/RPCBind)         |
| Protocol Type    | TCP and UDP                                          |
| Authentication   | None by default (relies on client-side UID/GID)     |
| Encryption       | None (unless combined with Kerberos or SSH tunnels) |

---

## 🔍 Footprinting NFS

Footprinting NFS aims to identify accessible exports, mount permissions, and potential for file manipulation or privilege escalation. Since NFS often lacks strong authentication, it’s essential to check for improperly shared directories or privilege mapping weaknesses.

---

## 🧰 Reconnaissance Techniques

### 1. Port Scanning

Scan for RPC and NFS services:
```bash
nmap -p 111,2049 -sV <target-ip>
```
### 2. List NFS Exports
Use `showmount` to enumerate NFS shares:
```bash
showmount -e <target-ip>
```
### 3. Mounting an NFS Share
Attempt to mount the export locally:
```bash
mount -t nfs <target-ip>:/exported/path /mnt/nfs
```

### 4. RPC Information Gathering
Enumerate RPC services running on the host:
```bash
rpcinfo -p <target-ip>
```
### 5. File Access Testing
Check read/write access within mounted shares. Look for sensitive files or the ability to inject scripts, binaries, or SSH keys.
### 6. UID Spoofing
If root_squash is not enabled, try creating a user with UID 0 and test privilege access on the share.

## 🛡️ Common Misconfigurations

- Exports accessible to `*` or large subnets
- Writable exports without root_squash
- No authentication or access control
- Using UDP (less reliable and harder to secure)
- Exporting system directories (`/etc`, `/home`, etc.)
